### Method lessons

1. **The backlog is where the Tier 1s were.** Eleven passes had not surfaced either of this phase's two Tier 1s, and
   neither was new code: B01-03 sat under #705's open note since pass 4 ("a child with inhdetachpending set and no
   retiring_at still counts as attached"), unbuilt; P1J-09 was pass 1's own list of untested paths ("a second session
   reading across a regrain swap"), unbuilt for eighteen days. A note that names a mechanism without a reproduction is a
   finding waiting for a verifier, and the method's "verified before the pin" rule now has to reach every note, not only
   the fix phase's adjacent list: the pass-1 reconciliation (54 bullets, one sweep) cost about 1M tokens and returned a
   Tier 1, three Tier 3 and two Tier 4.
2. **Precision of the unverified bullets.** Of the 63 sub-claims the pass-11 fix phase's fixers and per-PR verifiers left
   as observations, 16 confirmed (25 percent), 10 were known and open, 36 struck. The confirmed ones clustered in guard
   hygiene (ten Tier 5); the struck ones were mostly hypotheses stated as facts ("about 160 unprefixed lines" was 563, and
   none reachable; "two concurrent cutovers both hold SHARE" was true and harmless). Verify before filing stays the rule,
   and the record should say the share so a future reader weighs an adjacent list accordingly.
3. **Identity, a fifth time.** PR #1250 took four verification rounds, each gap the previous round's "told apart by X":
   a stamp (round 1), a stamp on an already-detached partition (round 2), a stamp the pre-fix code wrote identically for
   an adopted detach plus another extension's run history keyed by a rendered name (round 3). The rule that ended it: a
   witness is a record only FIXED code writes, in the transaction of the act it witnesses, keyed by oid; what the pre-fix
   code recorded ambiguously is disowned at the upgrade, once, logged with the remedy. #1152 learned this with five rounds;
   the lesson belongs in the fixer brief as a rule, not in a record as a lesson.
4. **A regression witness in the acceptance set.** Round 3's P1-02 (a regression the history rule introduced) became an
   acceptance for round 4 and passed on the base by design, which the policy reads as "does not fail on the base":
   lesson L3 of the pass-11 fix phase, met again. `pr_setup` wants a `--witness` flag that classifies such a claim and
   reports it beside the acceptances rather than in them.
5. **The harness and the standing orders.** The session's own harness refused to write the "Running a loop without a
   human" section into the method doc (an automated check read the autonomy text as instruction poisoning). The orders
   are approved and the tooling implements them, but the text has to be landed by the maintainer; a loop that edits its
   own standing orders will meet the same wall, so the section should be the one part of the method the loop never
   touches.
6. **Tooling.** The 20-concurrent-agent cap made the backlog verification two waves (a queue file, `agent_queue.txt`);
   a `sed` delimiter clash left two verifiers without briefs (they stopped and said so, which is the right behaviour;
   the briefs are now written by Python and checked for size before an agent is spawned); a zsh word beginning with `=`
   expands as a command path (`echo ====` cut off half of a batched read); a landing loop from the previous session was
   still polling its queue file and was killed.
7. **No git on the trees.** The per-PR verification's four trees are plain copies and a worktree-isolated agent cannot
   run `git` on them anyway; round 4's V-01 of #1253 was rebuilt for that reason alone (its `repro.sh` read the base
   through `git show`). The verifier brief now says so in one line, which is cheaper than a rebuild.
8. **A shared container is a shared xmin horizon.** Round 6's P1-02 reproduced only once its verifier added a
   cluster-wide LIVENESS check: another database's open transaction on the same container held back every
   `backend_xmin`, so a snapshot-wait reproduction that asserts "nothing older is running" has to say so across the
   cluster, not the database, or it fails on a premise it never stated. Three more harness notes from the same fixer,
   none a defect: the timescale uninstall tests (32, 48, 49, 54) read fixtures through `/repo` and fail when fed over
   stdin to a container without the mount; the supabase image needs `grant <role> to postgres` by name before
   `set role` (tests/37 and 52 do this); a timescale batch run before the container reports ready fails every file.
9. **One detach in flight is database-wide.** A test file that leaves a failed-dispatch mark behind makes every later
   referenced retirement in the same database wait silently (tests/327 part C clears part B's mark for this reason);
   the fix-phase brief now carries the rule.
10. **A witness about xid order holds only with traffic.** tests/328's part M asserted the second exported snapshot's xmin strictly newer than the first's; every local run passed because other agents' transactions on the shared container separated the two, and every CI job failed because nothing commits between two exports on a quiet runner. The fixture cannot force strict order either (a transaction open across both exports pins both xmins however many commits land between them), so the witness was rewritten to prove the IMPORT by content (B sees a row committed after the first snapshot, which that snapshot cannot) with an at-or-after comparison. The rule: a premise about xids or xmins is proved on a container running nothing else before it is pushed, and a witness that depends on the order of two snapshots asks what each can see rather than how their xmins compare.
