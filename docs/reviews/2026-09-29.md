### Tooling defects found by running the pass

1. `classify_claims.py` loads every `claim.json` under `--claims` before honouring `--only` or `--finders`,
   so a half-written claim file in a finder still at work (F8-07, 568 bytes, cut mid-string) crashed a
   verifier's `--only` run with a bare `JSONDecodeError` and no path. Worked around by classifying from a
   staging copy that holds only finished finders (`claims_final`); the fix is to scope loading to the
   selected claims and to report the offending path, classifying a malformed claim as invalid.
2. An archive claim (install list ending in `pgpm_archive/install.sql`) classifies as `not_run: install
   failed` in the core harness because it lacks the `http` extension, unless the finder sets `"container"`;
   the classifier should default the container from the install list.
3. The verifier brief did not carry the classifier's exact command line, and the sealed file it needs is one
   a verifier must not read; the brief now names a seeds-less copy (`sealed_for_verifiers.json`) and the
   full command.

### Tooling notes taken while running

- Tooling: `classify_claims.py` loads EVERY claim.json under --claims before honouring --only/--finders, so a
  malformed or half-written claim.json anywhere (F8-07 while F8 was still writing) crashes the run with a
  JSONDecodeError and no file name. The F7-03 verifier hit this and ran the reproduction by hand. Workaround
  this pass: finished finders are rsynced into pass4/claims_final and every classifier run reads that tree.
  Fix for the tooling PR: scope loading to the selected claims, and report the offending path, marking a
  malformed claim.json as `invalid_claim` instead of aborting.
- Verifier brief now carries the exact classifier command (with a seeds-less sealed file, so the verifier
  never sees the seed list) after the F7-03 verifier had to guess the arguments.
- Seeds and the test suite: F8 (fresh surface, opus) ran the tree's whole core and archive pgTAP suites plus the
  standalone bench guards, one database per file, and traced every non-environmental failure to its line. Every
  catalogue seed has a test-file guard by construction (a pass-3 fix = guard + mutation), and the three novel seeds
  each break an existing test too (tests/98, 134/122, 149), so all nine seeds were found by that one finder in
  20 minutes, before any lens-driven reading. Recall 9/9 therefore measures "the suite is run" at least as much as
  "the lens sees the defect". F10 (same slice, fable) found five seeds by reading. For pass 5: either plant seeds no
  existing test catches (mutate a path the suite does not exercise), or report recall split into suite-caught and
  read-caught; the methodology already says loud seeds measure nothing, and a seed the suite catches is loud to a
  finder who runs the suite.
- Archive claims (install lists pgpm_archive/install.sql) cannot install in pgpm_test-15 (no `http` extension) and
  classify as `not_run: install failed` unless the claim carries `"container": "pgpm_test-archive"`; neither F8 nor
  F10 set it. classify_finder.sh re-runs those in the archive harness and stamps the container into the record so
  the verifier brief names the right one. Fix for the tooling PR: default the container from the install list.
